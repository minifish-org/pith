# Pith embedded SDK migration rules

This is an additive, headless SDK migration from Pi f07218c4d4bbc12bef056a7058c3dd49dfe41abe (v0.87.1). It is NOT an upstream version upgrade. The accepted AI, agent-core, harness and tool packages are read-only dependencies. Preserve their files, public API and the original migration evidence. All new product files live under packages/coding-agent, examples/embedded-sdk and docs/sdk.

Build with CGO_ENABLED=0. Race checks may use CGO_ENABLED=1 as required by Go's race detector; product code must not require C libraries. Use the existing go.mod/go.sum; standard library and already approved pure-Go libraries are available. Do not install npm, shell out to Node/Pi or require a Pi binary in the resulting SDK. No subprocess boundary between a Go application and its embedded agent. Avoid hidden process-wide state and global model registration that makes independent sessions interfere.

Read the original source and relevant upstream tests before translating. API.go.txt freezes the minimum public integration surface, not implementation bodies; the stub is only an independent judge compile control and must never be copied as production code. Each contract includes additional behavioral requirements beyond the executable tests. Preserve the source behavior unless a Go adaptation or explicit exclusion is documented in scope.json and NOTES.md. Use existing Pith Agent, tools, AI providers, session/compaction/resources implementations where semantics match. The existing sdk.Run convenience loop is not the required coding-agent session implementation.

Keep one owner for each shared type; Go package cycles are forbidden. Default public import: github.com/minifish-org/pith/packages/coding-agent, package codingagent. It may organize implementation across the planned files in that package. Do not create unnecessary compatibility facades or reimplement the provider protocols. Do not artificially reduce context/output capacity. Pass caller/provider model capabilities through, handle length truncation and never execute incomplete tool arguments. Do not put fixed limits on migration repair attempts, candidate file size or per-session duration; callers may explicitly configure budgets and cancellation.

Custom Go tools/hooks replace JS execution plugins. Plain-text skills, project instructions and prompt templates remain resources. TS extension execution, TUI widgets, npm/Git extension package installation, remote service management and browser login UI are explicitly outside this increment. Headless credential callbacks and provider selection are in scope. This SDK is not a filesystem sandbox or enterprise authorization system; tool hooks must run before executing each tool and can deny it.

Every step must produce implementation, meaningful self-tests and its source_map JSON. Source maps record source, upstream, goPackage, goSymbol, goFile and reason for each selected export. If an export mixes excluded TUI/JS-host behavior with SDK behavior, record the adaptation in reason, not an unsupported parity claim. Files and declarations must really exist. Excluded exports require an explicit disposition and reason, not a fake symbol. Portsmith runs cumulative independent tests and existing product regression tests. Do not modify judges, omit tests, write skip-only tests, fake provider output or detect test names to produce answers.

Context cancellation must reach network I/O, running tools and child processes. Keep tool results paired with calls and persist coherent turn boundaries. Event ordering, callback lifetimes, session durability and usage reporting are public behavior. Long-run acceptance includes retry, truncation, compaction, queued messages, cancellation and reopen. Offline local fake-provider tests are mandatory; no paid model call is needed for verification. Passing these tests is evidence for the covered contract, not proof of all Pi behaviors or production readiness.
